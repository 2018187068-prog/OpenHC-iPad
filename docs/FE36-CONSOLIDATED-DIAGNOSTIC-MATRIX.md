# FE36 consolidated diagnostic matrix

This change adds case isolation and failure collection to the existing 21 FE36 auth and 10 Nearby cases. It is diagnostic harness work only: it does not change production transport, protocol, crypto, deadlines, lease ownership, trust, or key handling, and it does not claim a production defect is fixed.

Each case uses a new, exclusive guard directory and clears the shared result/status files before launch. The harness records a fixed outcome, a whitelisted assertion token and safe phase metadata even if an exception interrupts the case. It records no packet bytes, plaintext, ciphertext, PIN, key, identity, credentials, or connection-info content. Per-case evidence retains the simulator trace, proxy phase/timing and outcome metadata.

Continuation after a case requires the simulator launch response to identify its PID, observed process exit, and a stopped peer daemon thread. Listener and accepted sockets are shut down and closed in `finally`. Missing PID, unavailable process observation, launch/setup failure, unknown process state or a stuck daemon ends the matrix; remaining rows are explicitly `unrun`. No process is killed to manufacture isolation. A bounded assertion failure is collected only after process and daemon exit are established, and the matrix continues through remaining cases. Every collected failure makes the aggregate gate exit nonzero. The 21/10 suite markers are emitted only when every row passed.

`scripts/test-fe36-case-matrix.py` verifies early and late isolated failures reach later rows but still fail, unsafe/setup failures stop and mark remaining rows unrun, labels redact arbitrary text, process/daemon isolation is mandatory, and success markers cannot appear for partial matrices. Its simulator-process checks use injected adapters; they are not an Apple Simulator run. The full owner workflow runs the matrix on the actual Simulator and preserves its case artifacts.

The prior archived run `46108370359` failed in `background` at `encrypted_handshake_response` before the fixture writes its Stop request. Its trace timing is compatible with the 2000 ms common-session expiration; the archived error omitted the response kind/CID/frame validation branch, so the cause is still unresolved. This change adds fixed-label packet metadata and monotonic phase timing so one consolidated run can distinguish those branches and proceed to Nearby cases when each failed fixture is demonstrably isolated. It is not a root-cause correction and is not acceptance of the previously unrun Nearby cases.

Local Windows tests exercise actual Python typed-packet parsers and loopback sockets, matrix aggregation and injected lifecycle branches. They do not exercise the Apple Simulator, Native crypto runtime, UI, packages, or a phone. The production platform/network provider remains deny-all/injected. Rootless Theos package, macOS 15 workflow and `ldid -S` signing route are unchanged.
