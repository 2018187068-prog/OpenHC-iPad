## Observations added

The existing Python driver observes initial-state, control-listener, control-SDP, incoming-accept and bridge-start reads. Every complete transport header records only its fixed branch, kind, channel and declared size. Complete command headers additionally record numeric opcode and declared parameter length; unavailable fields are explicit. No packet, frame, payload, identity, key, PIN, ciphertext, connection information or arbitrary exception text is persisted. Existing fixed assertion labels and negative failure semantics remain intact. Unexpected cleanup commands still fail.

For observed command reads, at most the three-byte command header is read before the original transport-shape assertion, so an unexpected close retains its opcode. No unexpected command body is drained or interpreted as success. This uses the existing socket timeout and adds no retry, sleep or timeout. A truncated header retains the earlier numeric transport observation and fails on EOF/IO; subsequent reads do not proceed. Unobserved driver users retain their previous read behavior.

The C transport snapshots its pre-cleanup failing stage at its existing done label into a const pointer selected from a fixed whitelist. BTSTACK_FE35_INBOUND_PRIMARY_STAGE is emitted at the existing end-of-run reporting point. Cleanup can still set the final BTSTACK_FE35_INBOUND_FAILED stage and independent cleanup certainty. NONE means no pre-cleanup error was observed; UNCLASSIFIED fails to disclose an unlisted label. This snapshot records the current failing stage, not the kernel-level cause or every nested auth failure. No native packet-loop writes or protocol/API/timing changes were introduced.

## Measurement overhead

Per-phase diagnostic text and monotonic timestamps are now collected in memory, bounded to 4096 entries per case including an overflow marker. Overflow fails the case after isolation. Both files are attempted unconditionally in the existing case-finally after sockets and thread teardown, before copying evidence and before any success marker or guard deletion. Existing case evidence is preserved even if a proxy file write fails; write errors remain failures. No additional synchronous evidence rewrite occurs between SDP acknowledgement and incoming/open delivery. This removes an observer cost; it is not proof that observation overhead caused the previous failures. A host crash before finally can still lose buffered observations.
